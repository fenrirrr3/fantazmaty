WDROŻENIE
Wgraj ZIP obok manage.py. W Bash PythonAnywhere, w katalogu projektu, z aktywnym środowiskiem:

unzip -o import_archiwum_v12_wykonawcy_2026-10-05.zip -d .
python manage.py migrate
python manage.py check

Paczka zawiera poprzednią migrację 0015 dla spójności z v10. Nie ma nowej migracji. Nie usuwaj już zastosowanej migracji 0015 ani nie cofaj migracji bazy. Jeżeli v10 wdrożono, migrate nie powinno wprowadzić nowych zmian z tej paczki.

1. Podgląd korekty (wycofuje wszystkie próbne zmiany, także zmiany profili):
python manage.py repair_archive_executions --report raport_korekty_podglad

2. Jeżeli conflicts jest puste, zapis korekty:
python manage.py repair_archive_executions --apply --report raport_korekty_zapis

3. Następnie import aktualnego pliku danych:
python manage.py import_completed_table import_archiwum.json --apply --report raport_archiwum_zapis

Jeśli wszystkie 29 tekstów wcześniej zaimportowano i skorygowano, krok 3 jest kontrolą zgodności i nie dodaje rekordów. Jeśli import nie był jeszcze zapisany, tworzy teksty zgodnie z nowym podziałem. Warunkiem są istniejące docelowe antologie. Nie uruchamiaj kroku 3 po konflikcie z kroku 1/2.
Po zakończeniu kliknij Reload w zakładce Web PythonAnywhere. Collectstatic nie jest potrzebne — zmieniono Python i szablony, bez statycznych CSS/JS.

ZABEZPIECZENIA I ZAKRES
- Naprawa obejmuje wyłącznie źródło archive-table-2026-10-05-22 i wiersze 1–29. Ta nazwa źródła celowo zostaje bez zmian.
- Plik archiwum_przed_korekta.json jest wzorcem poprzedniej wersji v11, nie służy do ponownego importowania. Plik import_archiwum.json zawiera nowe mapowanie.
- Dla już zapisanych tekstów aktualizowane są przypisania/etapy w miejscu: ich ID i powiązania pozostają zachowane. Nie kasujemy tekstów, autorów, etapów ani przypisań.
- Technicznie wykonania weryfikacji używają first_verification/verifier_1, a korekty first_proofreading/proofreader_1 z numerami wykonania 1…N. Widoki tych 29 archiwalnych tekstów pokazują Weryfikacja/Korekta/Redakcja — wykonawca N, także pierwszy. Aktywny workflow pozostałych tekstów zachowuje własne etapy.
- Widok zespołu i tabela workflow zachowują osobne wykonania tej samej osoby.
- Korekta odmawia nadpisania tekstów, których tytuł, długość, autorzy, wykonawcy, etapy lub daty zmieniły się od importu. Rozbieżność wycofuje całą transakcję, również zmianę nazwiska. Raport wymienia przyczynę.
- Nie dopisujemy fikcyjnych dat, nie nadajemy uprawnień ani haseł. Dotychczasowe e-maile zostają zachowane.
- Raport JSON korekty zawiera identyfikatory oraz stan etapów i przypisań przed zmianą. Podsumowanie pojawia się również w konsoli; nie powstaje HTML.
- Ponowne uruchomienie korekty oraz import nowego JSON po korekcie nie powielają wykonań.
